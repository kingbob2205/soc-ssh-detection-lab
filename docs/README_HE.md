# מעבדת זיהוי ותגובה לניסיונות פריצה ב־SSH

פרויקט SOC מעשי שבניתי: מכונת Kali מריצה סימולציה מבוקרת של ניסיונות סיסמה שגויים מול שרת Ubuntu ברשת מבודדת. את לוגי ההתחברות חקרתי ב־Splunk (SIEM), ו־Fail2ban חוסם אוטומטית את כתובת התוקף באמצעות nftables.

## תוצאות (17/10/2026)

- **זיהוי:** Splunk קלט 16 אירועי SSH. חיפוש SPL חילץ משתמש, IP ופורט ומצא 3 כישלונות סיסמה מכתובת התוקף.
- **תגובה:** Fail2ban חסם את 10.77.0.10 אחרי 5 אירועים תואמים בתוך 60 שניות. כלל nftables אומת, והחיבור הבא מ־Kali נדחה (Connection refused).
- **תיעוד:** ציר זמן, חקירה ומגבלות מופיעים ב[דוח האירוע](INCIDENT_REPORT.md). צילומי מסך נמצאים בתיקיית `evidence/2026-10-17/`.

## מיומנויות

ניתוח לוגים בלינוקס, Splunk SPL (rex, stats, זיהוי לפי סף), Fail2ban ו־nftables, רשתות מבודדות, כתיבת דוח אירוע, Python ובדיקות CI.

## השלבים הבאים

הרצה נוספת כדי להפעיל את התראת הסף ב־Splunk ולצלם את הדשבורד, בדיקת שחרור החסימה, והעברת לוגים רציפה עם Universal Forwarder.
